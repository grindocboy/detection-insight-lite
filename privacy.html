Privacy and verification

Your detection stays in your browser.

Detection Insight Lite has no application backend, accounts, database, analytics, cookies, telemetry, advertising, or external API calls. Rule analysis runs as JavaScript in the browser tab you opened.

Technical enforcement

The site declares a Content Security Policy containing connect-src 'none'. Compatible browsers block outbound fetch, XMLHttpRequest, WebSocket, EventSource, and beacon traffic from the application. The policy also blocks forms, frames, plug-ins, workers, and third-party scripts.

What remains on your device

  • The detection text in the editor exists only in the current page memory.
  • No detection is written to localStorage, sessionStorage, IndexedDB, cookies, or a service worker.
  • A report is created only when you choose Download report.
  • Sanitized text enters your clipboard only when you choose Copy sanitized rule.
  • Closing or refreshing the tab discards editor contents that you did not download or copy.

Hosting metadata

GitHub Pages serves the static files and may process ordinary web-request metadata such as IP address, browser details, requested URL, and timestamp under GitHub's own policies. Detection text is not placed in the URL and is not transmitted with those page requests.

Verify it yourself

  1. Open browser Developer Tools and select the Network panel.
  2. Clear existing entries, paste a non-sensitive test rule, and select Analyze detection.
  3. Observe that analysis produces no network request.
  4. Inspect the public source and search for fetch, XMLHttpRequest, WebSocket, sendBeacon, storage APIs, and third-party scripts.

Important limitation

This design greatly reduces disclosure risk, but users should still avoid pasting live credentials, customer data, classified information, controlled unclassified information, or proprietary detections into any public website. Use an approved offline copy for sensitive environments and review the exact source before use.
